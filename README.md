# KeyRinger Audio Protocol — Reverse-Engineered

A complete, verified reconstruction of the audible-tone control language used by
**KeyRinger** key/phone finders — the devices sold at
[keyringer.com](https://www.keyringer.com) that "call" each other through
ordinary speakers and microphones.

The vendor publishes a page ([call-keyringer](https://www.keyringer.com/call-keyringer))
with 17 playable tone buttons, and a
[zip-files page](https://www.keyringer.com/zip-files)
hosting their **entire original tone library: 5,869 tone files** plus the
vendor's own circa-2013 control page (`audio1.htm`, a table-driven
JavaScript form that maps user input to tone file names). This repository
documents what those tones mean.

**The protocol was recovered statistically, not by disassembly**: all 5,886
tone files (vendor library + live site audio) were decoded signal-by-signal,
and the resulting grammar was re-encoded and compared back. Final state:

| Layer | Coverage | Result |
|---|---|---|
| Calling/address frames | 4,492 vendor files + 16 live files | **100% symbol-exact** round-trip |
| Programming/command frames | 1,375 vendor files | **100% symbol-exact, all 17 slots** (slot 17 from the published vendor table) |
| Slot 17 check symbol | 1,375 files | deterministic; closed-form rule not recoverable — full truth table published instead |
| Filename ↔ decode agreement | 5,867 vendor files | **5,855 direct matches**, 12 explained by one-hot volume encoding, 3 legacy/special files documented separately |

No vendor audio files are redistributed here; the example WAVs are generated by
this repo's encoder.

## What is a KeyRinger?

Sold in identical pairs: you attach one unit to your keys and one to, say, the
TV remote. A **double-click** of the blue button on either unit emits a ~2-second
tone sequence through its speaker; the other unit spends its life *listening for
that exact sequence* through its microphone, and when it hears it, it beeps and
flashes (default 15 s; programmable 5 s–4 min) to be found. The calling unit
also makes the sound, which is how you know the call was sent. The called unit
ramps its response volume up gradually so as not to startle anyone.

Because the whole system is just "play tone X, listen for tone X," the vendor's
website can do the calling too: any PC/phone speaker can summon any unit.
That is the mechanism documented here.

Product facts (vendor documentation): CR2032 battery, all units sold since 2014
are identical and compatible; units sold before January 2013 used a different,
incompatible detection algorithm (see [legacy protocol](docs/legacy.md));
programmable via speaker-played commands after entering programming mode
(hold button ~3 s, release at first light → long-short-long beep + double flash;
programming mode lasts 4 minutes).

## The two frame types

### 1. Calling frames (who should ring)

- **Sync**: 1.171 s continuous tone at **4098 Hz** (symbol `B`).
- Then **L slots of 0.17705 s**. Symbols: `A` = 4032 Hz, `B` = 4098 Hz,
  `C` = 4167 Hz.
- The payload is **differential**: the bit is the *transition* between
  consecutive slots, not the symbol itself:

  | bit 0 | bit 1 |
  |---|---|
  | `A→B`, `B→C`, `C→B` | `A→C`, `B→A`, `C→A` |

- **Universal (group) frames** — anchor `A`, then `L` transition bits,
  LSB-first. `L` = 5–8 (short/long signal length), group values 0–255.
- **Unique (individual) frames** — anchor `C`, then a **long-code flag**
  transition (1 when value ≥ 16 — exactly the vendor's own
  `value < 16 ? short : long` rule), then `L−1` data bits, LSB-first.
  `L` = 5–12, values 1–2047 in the vendor library.

A universal call answers on every unit in the group; a unique call answers on
exactly one unit.

### 2. Programming/command frames (what to change)

- Same 1.171 s `B` sync, then **17 slots of 0.2441 s**, plain binary:
  `A` = 0, `B` = 1.
- Layout (1-based slots):

  | Slots | Field |
  |---|---|
  | 1 | anchor `A` |
  | 2–9 | value byte, LSB-first (one-hot for the four volume commands) |
  | 10–14 | 5-bit opcode, LSB-first |
  | 15 | opcode-extension flag |
  | 16 | even parity over slots 2–15 |
  | 17 | second check symbol (see below) |

- 20 command opcodes recovered, identical to every command family referenced
  by the vendor's own archived control page: set group code, set unique
  receiver / transmitter-base codes (16-bit, split into lo/hi bytes),
  response duration, double-click window, four volume settings, signal
  lengths, detection window/thresholds, flicker-LED, low-battery alert,
  factory reset. Full table: [`data/opcodes.json`](data/opcodes.json).

Slot 17 is deterministic in (opcode, value) — identical frames never disagree —
but no closed-form rule fits it (tested: all parity windows, GF(2)/GF(3) linear
functions, CRC-8 family, Hamming syndromes, Luhn, decimal digit sums, and more).
Since a receiver only needs to *check* slot 17, the complete per-value truth
table is published in [`data/slot17_table.json`](data/slot17_table.json).

## Quickstart

Needs Python 3.10+; numpy only for the decoder.

```bash
# generate a "call unique ID 7" tone (plays ~2.2 s on any speaker)
python3 tools/keyringer.py encode --family unique_5 --value 7 call7.wav

# generate a programming tone: response duration = 30 (needs unit in programming mode)
python3 tools/keyringer.py encode --cmd response_duration=30 resp30.wav

# decode any KeyRinger tone file (wav, or mp3 if ffmpeg is on PATH)
python3 tools/decoder.py call7.wav
```

`decode` output for `call7.wav`:

```json
{"kind": "calling", "family": "unique_5", "value": 7, "symbols": "CBACAB", ...}
```

Round-trip self-test (encoder → WAV → decoder, across every family):

```bash
python3 tools/verify_roundtrip.py
```

## Reproducing the analysis

The tone corpus itself is not redistributed (it is the vendor's audio). Point the
manifest builder at a directory of tone WAVs and it will regenerate the decode
evidence:

```bash
python3 tools/manifest.py /path/to/wavs out.csv
```

Then compare `out.csv` against the file names: vendor file names *are* the
ground truth (`universal_8_42.mp3` etc.), which is what makes the verification
self-checking. See [docs/analysis.md](docs/analysis.md) for the exact pipeline
and numbers.
