# The KeyRinger Product and Its Programming Model

Product facts below come from the vendor's own documentation pages (fetched
November 2026) and are relevant because the protocol exists to serve exactly
these behaviors.

## Hardware and use model

- Sold in **identical pairs**; each unit has one blue double-click button, a
  red LED, a speaker, a microphone, and a CR2032 battery.
- Double-click → ~2 s tone sequence out of the speaker ("the KeyRinger in your
  hand makes a sound so you know the call was sent").
- Every unit listens continuously for its tone sequence; on hearing it, it
  beeps and flashes for the configured response duration (default 15 s;
  programmable 5 s–4 min), starting at the *min response volume* and ramping to
  the *max response volume* so it doesn't startle anyone. Press its button to
  silence immediately.
- The red LED flashes about once per second in normal operation (a "still
  alive" heartbeat; LED flicker mode is a separate programmable feature).
- Range is speaker/microphone limited (same room through cushions and light
  obstructions; vendor FAQ attributes missed calls to distance/obstruction and
  the two-second detection window).
- The vendor sells every unit sold since 2014 identically, and any 2014+ unit
  can call any other; the site's own call page can call any unit because the
  calling side is just audio.

## Device state (what the command frames program)

From the vendor's archived control page (field names preserved):

| Field | Range | Default | Command opcode |
|---|---|---|---|
| receiver number | 1–2047 (16-bit) | 1 | `uniq_code_rcv_lo/hi` |
| transmitter base number | 16-bit | 0 | `uniq_code_xmit_base_lo/hi` |
| group ID | ("universal number") | 1 | `universal_code` |
| CU1…CU10 call buttons | unique codes <16 → short, else long | — | `unique_L_V` frames |
| double-click speed | 0.1–1.0 s | 40 (≈0.4 s) | `double_click_speed` |
| response duration | seconds | 15 | `response_duration` |
| min/max response volume | 1–5 | 1 / 4 | `min/max_response_volume` |
| min/max call volume | 1–5 | 3 / 4 | `min/max_call_volume` |
| duration each call volume | step seconds | 1 | `duration_each_call_vol` |
| flicker LED | on/off | off | `flicker_led` |
| disable low-battery alert | on/off | alert on | `disable_low_battery` |
| short signal length | 5–8 slots | 5 | `signal_length_short` |
| long signal length | 6–13 slots | 8 | `signal_length_long` |
| detection window size | 1–6 | 4 | `detection_window_size` |
| short detection threshold | 4–64 | 12 | `threshold_12` |
| long detection threshold | 16–128 | 32 | `threshold_25` |

Volume levels are labeled Extra Quiet / Quiet / Medium / Loud / Extra Loud
(current site: Very Soft → Very Loud, default max).

## Programming workflow (vendor docs, current site)

1. Enter programming mode: hold the blue button until the LED lights
   (~3 s) and release immediately. Confirmation: long-short-long beep and two
   quick LED flashes. The unit stays in programming mode for 4 minutes or
   until you click the button.
2. Play one command tone through any speaker (the site's ▶ buttons, or any
   file generated by this repo's encoder). ~6 s tone.
3. Success is acknowledged by the same long-short-long beep + double flash.
4. Click the button to exit.

To *assign* a unique ID, the site plays the `unique_L_V` calling frame of the
chosen value while the unit is in programming mode — the same frame that later
*calls* it. Verification mode: hold-and-release at the double-beep, then the
LED counts out the ID's digits in flash groups.

## The retail call page today

The live call-keyringer page has 17 buttons. MD5-matched against the vendor
tone library:

| Button | Tone file | Protocol |
|---|---|---|
| CALL ALL | `universal_5_1` | group 1 (factory default group) |
| unit 1 … unit 14 | `unique_5_1` … `unique_5_14` | individual IDs 1–14 |
| CALL DOMINO | `universal_5_5` | group 5 |
| CALL ORIGINAL | `keyringer1.mp3` | legacy pre-2013 call |

`short.mp3` in the vendor library is a 72 ms DC-bump placeholder used by the
old page's audio element (no protocol content).

## Generations

- **Pre-January 2013** units: original detection algorithm; incompatible with
  everything after (vendor FAQ). The `CALL ORIGINAL` button plays the legacy
  call tone documented in [legacy.md](legacy.md).
- **January 2013**: "a new and much improved algorithm was introduced to
  detect the tones" (vendor FAQ) — the differential FSM described in
  [protocol.md](protocol.md).
- **2014+**: all current units; identical hardware; group IDs (site assigns
  1–9) and unique IDs (site assigns 1–13, call page calls units 1–14, protocol
  allows 1–2047).
